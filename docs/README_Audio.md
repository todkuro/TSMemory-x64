# 音声を取り込む (AAC)

TSMemory の**任意機能**です。既定では無効で、有効にしない限り
音声側のコードは一切動きません。

本体の説明は [README.md](../README.md) を参照してください。
対応するまでの調査メモは [audio-support.md](audio-support.md)、
実装上の判断は [development.md](development.md) にあります。

---

## 1. 両方の ini を有効にする

**片方だけでは音声は出ません。** TVTest 側で落とされると
AviUtl2 側では何もできない為です。

    TSMemory.ini (TVTest 側)           TSMemory-TVTestSrc.ini (AviUtl2 側)
    [Settings]                         [M2V]
    Audio=1                            audio=1

TVTest 側は `CTsSelector` に AAC の PID も残させる設定、AviUtl2 側は
その PID を読んで復号する設定です。**どちらも既定は 0** です。

### なぜ両方とも既定で 0 なのか

字幕 ([README_Subtitles.md](README_Subtitles.md)) は TVTest 側だけ
既定で 1 にしてありますが、音声は違います。**溜め込みの費用が
桁で違う**為です。

| | ストリームに占める割合 (実測) | 既定 |
| --- | --- | --- |
| 字幕 | 0.01〜0.02% | TVTest 側は 1 |
| 音声 | **約 2%** | 両方とも 0 |

音声を溜めると、同じ `MemorySize` で遡れる時間がその分短くなります。
静止画キャプチャが主な用途なので、要る人だけが有効にする形に
してあります。

**TVTest 側の変更には TVTest の再起動が要ります。**`Audio` は
`CTSMemory::Initialize()` でしか読まない為です。AviUtl2 側の `audio`
は取り込みの度に読むので、AviUtl2 の再起動は要りません。

## 2. 取り込む

いつも通りキャプチャ実行キーを押します。取り込んだ映像に音声が
付いた状態でタイムラインに置かれます。

うまくいくと AviUtl2 のログにこう出ます。

    TSMemory: 音声を取り込みました (2 ch / 48000 Hz / 11.94 秒 / 映像との差 +0.750 秒)

「映像との差」は音声が映像より**どれだけ先に始まっているか**です。
プラスなら音声の先頭を捨て、マイナスなら先頭に無音を詰めて、
映像と頭を揃えます。リングバッファは GOP の途中で切れるので、
映像と音声で開始位置が必ずずれる為です。

ログウィンドウは古い行が流れてしまうので、
`C:\ProgramData\aviutl2\Log\aviutl2_*.log` を見るのが確実です。

## 音が出ない時

いちばん多いのは**片方だけ設定した場合**です。その時はログに理由が
出ます。

    TSMemory: 音声が見つかりません。TVTest 側の TSMemory.ini で
    [Settings] Audio=1 になっているか確認してください
    (両方を 1 にする必要があります)

`[M2V] audio=1` だけ入れて TVTest 側が `Audio=0` のまま、というのが
起きやすい間違いです。この時に何が起きるかを実測しました。

| | |
| --- | --- |
| 音声 | 出ません |
| 一時的なメモリ | 共有メモリ全体 (= `MemorySize` 相当) を 1 部余分に複製します |
| 時間 | 約 1ms/MB を無駄に使います (既定 10MB なら 10ms 程度) |
| 空の音声トラック | 出来ません |

無駄が生じるのは `CTsSelector` が PMT を書き換えない為です。音声 PID
のパケットは落とされているのに PMT には載ったままなので、AviUtl2 側は
音声 PID を見つけて走査し、**走査し終わってから**「1 つも無い」と
判ります。害はありませんが、音声が要らないなら両方 0 に戻してください。

**4K/8K では音声の形式が違います。**設定は正しいのに音が出ない場合、
その旨が出ます。

    TSMemory: 音声はありますが対応していない形式です (stream_type 0x11)。
    対応しているのは AAC (ADTS, stream_type 0x0F) だけです

こう出た時は設定を疑う必要はありません。取り込み対象からは落として
いない (`TSMemory.tvtp` が `STREAM_AAC_LATM` / `STREAM_MPEG4_AUDIO` も
残す) ので、AviUtl2 側が復号出来るようになれば設定を変えずに出ます。

復号そのものに失敗した場合は理由が付いて出ます。

    TSMemory: 音声を取り込めませんでした : <理由>

## 設定一覧

TVTest 側 (`TSMemory.ini`)

| 設定 | 既定 | 説明 |
| --- | --- | --- |
| `Audio` | 0 | 音声 (AAC) の PID も溜め込むか。**変更に TVTest の再起動が要ります** |

AviUtl2 側 (`TSMemory-TVTestSrc.ini`)

| 設定 | 既定 | 説明 |
| --- | --- | --- |
| `audio` | 0 | 音声を開いて AviUtl2 に渡すか (`[M2V]` 節) |

音声だけの設定はこの 2 つです。音量や書き出しは AviUtl2 側の機能に
なります。

## 仕組みと費用

**復号は Windows 標準の Media Foundation に任せています。**追加の DLL
は要りません。m2v 自身も音声デコーダを持っていますが、Program Stream
専用かつ MPEG-1/2 Audio Layer II 専用で、日本の放送の AAC を扱えない
為に使っていません。

**取り込んだ分をまとめて復号してメモリに置きます。**48kHz ステレオで
およそ **1 分あたり 11MB** です。確保量は取り込んだ長さから決まるので、
`MemorySize` を大きくしても音声だけ途中で切れる事はありません。

**リングバッファは音声 PID の分だけ余分に食います。**上記のとおり
ストリームの約 2% なので、同じ `MemorySize` で遡れる時間はその分
短くなります。

## できない事

- **音声トラックは 1 本だけです。**PMT に複数の AAC がある番組
  (二か国語など) では、**先に見つかった 1 本**を使います。切り替えは
  できません。
- **4K/8K の音声は復号できません。**復号できるのは AAC の ADTS
  (stream_type 0x0F) だけです。4K/8K の LATM (0x11) と MPEG-4 raw
  (0x1C) は**溜め込みからは落としていません**が、AviUtl2 側で音には
  なりません (上記の警告が出ます)。映像 (H.264 / H.265) も同じく
  溜め込みますが、m2v は MPEG-2 しか復号できません。
- **音声だけを取り込む事はできません。**映像と一緒に取り込まれます。
  音声だけを有効にする設定はありません。
